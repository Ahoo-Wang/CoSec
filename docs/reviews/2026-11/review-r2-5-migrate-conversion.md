# Review round 2, part 5: the correctness of `cosec-migrate`'s conversion

Base: `origin/main` at `a0180e21b`, read 2026-11-20. Read-only, nothing changed, nothing run (no Gradle, no mutants, no benchmarks). Written by the session that took Pass B.

**The question (from the coordinator):** is there a 7.x policy set for which the converted 8.0 documents permit a request the 7.x engine denied (a DENY dropped or narrowed, an ALLOW widened, a condition or matcher translated to something weaker, a tenant or app scope lost, an ordering difference that mattered in 7.x), or silently convert to something that then fails closed for everyone? For each translator: what it refuses, and whether the refusal is loud.

**Answer in one paragraph.** Inside the translators, no: every path I followed either translates exactly, translates in the safe direction (ALLOW narrower, DENY wider) and records it, or rejects with a location; a DENY is never dropped (`StatementTranslator.assembled`). The two ways I found for a converted DENY to stop applying are **outside the translators' own question**, and both are about the one thing the translators cannot see: 8.0's route map. A converted DENY written on the `http:` vocabulary, or with a condition on `request.path`, `request.method` or `request.path.var.*`, does not apply to a request a route map maps, and the conversion says so for ALLOWs only (R2E-1). Second, the guard I would trust most, a differential test against a 7.x evaluation of a whole deployment, does not exist: the oracles are per condition and per action (R2E-2). No S1, no S2. Two S3 and two S4, none breaking after RC.

## Findings

### R2E-1 (migrate, S3, breaking after RC: no, size S) A converted DENY stops applying to a mapped route, and the conversion tells of ALLOWs only: for a DENY on `http:` there is a WARN at install, for a condition on `request.path` or `request.method` there is nothing

- **Where.** `MatcherTranslator.path` / `StatementTranslator.translation` (a path action becomes `http:*` or `http:<METHOD>` with `http:path:<pattern>` resources; an every-action DENY stays `*`), `Parts.FIXED` and `Parts.PREFIXES` (`request.path` to `resource.id`, `request.method` to `action.verb`, `request.path.var.x` to `resource.var.x`), `SemanticScan.everyActionAllowed` (C8, ALLOW only), `upgrading.md` C7 and C8 and "Every action is every HTTP request", against `RouteMap.escapes`, `HttpStatements.httpStatements` and `RouteEscapeReview`.
- **Input.** A 7.x deployment with `{"effect": "deny", "action": {"path": {"pattern": "/admin/**"}}}` (or `"action": "*"` with `{"startsWith": {"part": "request.path", "value": "/admin"}}`, or `{"eq": {"part": "request.method", "value": "DELETE"}}`). The conversion accepts, and says nothing about either. The operator then does what 8.0 recommends and loads a route map (for instance one generated from OpenAPI) that maps `GET /admin/users/{id}` to `admin:read` on `user/{id}`.
- **What happens.** A mapped request is `admin:read` on `user/<id>`, not `http:GET` on `http:path:/admin/users/1`. The first DENY has `http:*` and an `http:path:` resource: it does not match. The two conditions read `resource.id` (now the id, not the path) and `action.verb` (now `read`): they are false. In each case the request meets no DENY it met in 7.x, and is permitted wherever an ALLOW for the mapped action exists, which the operator has just written for the route map. `RouteEscapeReview` (UC-1) is the only guard: it logs one WARN per installed revision for a DENY or rate limit rule that is `http`-shaped (`httpShaped`: an `http` action pattern or an `http:path:` resource), and it reads **actions and resources only**. A statement on `*` with a condition on `resource.id` or `action.verb` is not `http`-shaped (`HttpStatement`'s KDoc: "one on every action and every resource applies to the mapped request as well": true of the statement, false of its condition), so nothing is logged.
- **Why it is asymmetric.** The ALLOW side of the same effect is loud: the route is `403` on the day the route map is added, and the report has a C8 line per ALLOW of every action. The DENY side fails open, and is recorded in the report and on the page nowhere (C7 is about a DENY of every action refusing *more*).
- **Not a regression of the conversion's own rule.** The converted documents, as converted, permit what 7.x permitted (`MIG-1` holds for what the conversion fills). The weakness is in the pair (converted DENY, later route map), and the converter is the only place that knows which DENYs are written in the unmapped vocabulary.
- **Fix.** (a) The report records each DENY and each rate limit rule that is `http`-shaped or reads `resource.id`, `action.verb` or `resource.var.*` as a SemanticChange of its own (`C9`: "a route map takes the routes it maps out of this DENY; rewrite it for the mapped action"), and `upgrading.md` says so beside C8. (b) `RouteEscapeReview` also warns for a DENY or rate limit rule whose condition reads `action.verb`, `resource.id` or `resource.var.*` (the compiled condition has its attributes; a statement whose action and resource are `*` and whose condition reads one of those is the shape). (c) Better for the first case: translate `startsWith(request.path, X)` in an every-action statement into a resource pattern as the `path` condition type already is, so the DENY has a resource a route map's `escapes` can compare. S. Each part is a normative rule (one in `MIG`, one in `RTE`) with a positive and a negative scenario (`verifyRuleCoverage`).
- **Smaller, same family.** A string predicate on `request.path` reads `resource.id`, which for an unmapped request is the path as received, *encoded* (`web.md`, "not decoded"), `;` parameters removed. 7.x read the raw `requestURI`. A DENY `startsWith(request.path, "/admin")` does not stop `/%61dmin/x` in either version, so nothing regresses; but the conversion carries the 7.x hole over unremarked while the same page tells the operator how a DENY on a pattern avoids it (`decodeAndParseSegments`). A one-line note in the report for a DENY-direction string predicate on `request.path`.

### R2E-2 (migrate tests, S3, breaking after RC: no, size M) Nothing compares a whole 7.x deployment with its conversion: the guards are per condition, per action and by example, and what composes them (layers, role scopes, grants, bindings, tenants) is read by nobody but a reviewer

- **Where.** `ConditionTranslatorTest` ("every row agrees with 7x on adversarial requests, never widening": the 7.x side is the mirror's matchers over `Facts`), `MatcherTranslatorTest` (translation examples), `ConvertedReachPropertyTest` (`MIG-2` only: which *actions* a converted deployment grants), `ConverterTest` and `Round2ConversionTest` (examples), `MIG.json` (`MIG-1` is a statement about the whole conversion; its guards are the per-row and per-example tests above).
- **What is missing.** The mirror holds 7.x's matchers, `Policy.verify` (DENY first, then ALLOW, inside a policy) and `RoleScope`, not 7.x's `SimpleAuthorization`: the order of the layers, how a role's grants are looked up for a request's space, how the global index is read, what an anonymous principal runs, what happens to a principal's attached policies. A conversion bug in the *composition* (a binding's scope, a grant's space, which document a policy lands in, the `directions` of a policy condition shared or pushed down, the `*` grant) is therefore seen only by an example someone wrote. I followed each of those by reading and found none (see the sound list), and I could not follow 7.x's own layer order, which is the half I would most want an oracle for.
- **Why S3.** The failure direction of this class of bug is the permissive one (a scope that comes out wider, a DENY placed where a principal does not reach), and `MIG-1` says it never happens.
- **Fix.** A property test in `migration/migrate/src/test`, in the shape of `ConvertedReachPropertyTest`: a small 7.x evaluator over generated deployments (global policies, attachable policies, app permissions with DENY and ALLOW members, grants of bare and spaced roles, principals with roles in several spaces and attached policies, in two tenants and the platform, anonymous), written from what the 7.x data model says and what `upgrading.md` states of 7.x (layer order, `RoleScope`, the global index), and the converted deployment asked through `ConvertedReach`/`Pipeline` with the same requests; every case where 8.0 permits and 7.x denied is a failure, every case the page lists as intended (C1 to C8, D1 to D4) is excluded by name. The evaluator is the part that needs the 7.x source and a person who read it. M.

### R2E-3 (migrate, S4, breaking after RC: no, size S) A policy in the global index of another type is converted as attachable, with a warning: if 7.x applied the index without the type test, a DENY is dropped

- **Where.** `Run.isGlobal` (`return inIndex && type == PolicyType.GLOBAL`; the `inIndex && type != null && type != GLOBAL` branch warns), `upgrading.md` ("converted as an attachable policy, since 7.x did not apply it to everyone"), `ConverterTest` ("a non-global type in the global index is converted as attachable, with a warning").
- **What is wrong.** The sibling case, a `GLOBAL` policy outside the index, is a rejection (`GLOBAL_TYPE_NOT_INDEXED`), and its message says the same thing about 7.x from the other side. Both rest on one claim about 7.x's loader (a policy is global exactly when it is in the index *and* of type `GLOBAL`), which the mirror does not contain and I could not check. If the claim is right, nothing is wrong. If it is wrong in the first branch, a DENY policy listed in the index with type `CUSTOM` applied to everyone in 7.x and applies to no one after conversion, on a warning.
- **Fix.** Where the policy holds a DENY statement, reject instead of warn (the same text as the other branch, "7.x's rule for this is not certain; set the type or remove it from the index"). Sound under both readings, one line, and loses nothing the claim is right about. S.

### R2E-4 (migrate docs, S4, breaking after RC: no, size S) Nothing tells the operator to stop changing policies between `convert` and the cutover, and nothing compares the data `publish` writes with the data `convert` read

- **Where.** `CoSec7xReader.keys` (a `SCAN` per namespace, then a `GET` per key and a separate `HKEYS` of the global index), `Source7x.inputSha256` (recorded in the report and printed by `convert`, "Input sha256 …"), `PublishCommand` (I did not read it; `inputSha256` is used nowhere else in the module: `grep` finds it in the reader, the export, the report and `ConvertCommand`), `upgrading.md` "Migrating the data".
- **What is wrong.** A `SCAN` returns every key that existed for its whole length, and may or may not return one added or removed during it; the global index is read in its own call. A 7.x instance that is still serving and whose operators add a DENY policy while `convert` runs, or after it, has that DENY missing from the converted deployment, with nothing in the report. The index-without-content and type-without-index checks catch half of the race (the index and the policy disagreeing); a *new* policy that is in both is simply absent. The page says "After `publish`, change policies through the control plane only", and does not say what to do about 7.x's policies before.
- **Fix.** The page says to stop writing policies (and grants, and the global index) in 7.x from `convert` until the traffic is on 8.0, or to run `convert` again and compare the `Input sha256`, which is what the hash is for: `publish --input-sha256 <hash>` that re-reads and refuses on a difference is the check; the sentence is the minimum. S.

## Sound, followed in the code

- **A DENY is never dropped or narrowed silently.** `assembled`: a condition that can never hold rejects (for either effect: loud); an ALLOW with no action left is `Dropped` and recorded, a DENY with none is rejected ("dropping it would permit what 7.x denied"); `head()` rejects a DENY on HEAD without GET (`PIP-18`: 8.0 decides HEAD as GET); `policy()` rejects a policy whose condition cannot hold. `translation()` and `policy()` translate each condition in the direction of its statement; `bool` keeps the direction through `and`/`or`; `negate` flips it, the way `translate` does; `statementDeny` is carried for the HEAD rule.
- **Directions and the safe side.** ALLOW may be narrower (D1 `inRole`, `ASCII-CASE`, `NOT-IN-8.0`, a template `eq` that no longer matches an absent part, HEAD removed from an ALLOW), DENY may be wider (D1 bare `inRole` in a DENY, `regular` `lit.*` as `prefix` only in the DENY direction and only without letters). Everything else rejects with a location.
- **`inRole`, against the 7.x matcher itself.** 7.x: `roles.contains(value)` (literal), then, for a bare value, a role that `RoleScope.roleIdIn(requestSpace, r)` maps to it (that is, `x@<requested space>`; bare `x` equals the literal, so the second step adds only the spaced one). 8.0: `subject.roles` is the bare ids over every space, `subject.scopedRoles` is `r` in the default space and `r@s` elsewhere, `scope.roles` is the roles in effect in the request's space. A DENY `x@s` is `scopedRoles contains x@s` (the literal), a bare DENY is `subject.roles contains x` (a superset of the 7.x set: wider, safe); an ALLOW `x@s` adds `scope.space == s` and an ALLOW bare `x` is `scope.roles contains x` (a subset: narrower, safe). Malformed values (empty parts, two `@`) reject; a role that 7.x would read as malformed applies nowhere in both.
- **Role grants and spaces.** `grantBindings`: one binding per granted permission, `Role(null, r)` in the app's document, `BindingScope(app exactly, space exactly)`, the default space being `""` on both sides (`SpaceIdCapable.DEFAULT`, `SpaceId.DEFAULT`). 7.x's `RoleScope`: a role `r@s` applies only in space `s`, a bare role only in the default space, a malformed one nowhere, and the grant key `role@space` matches exactly the principals that function gives the role in that space. A grant is therefore scoped as 7.x scopes it; a request that names another space is `scope-rejected` by `ScopeResolver` (C3, narrower). `*` in a grant is one policy holding every permission in `permissionIndexer` order; a permission nobody is granted is not emitted, so its DENY is not applied to a role it was not granted to (as in 7.x); a grant of an undefined permission rejects (C6).
- **Global policies.** An `Anyone` binding with `Match.Any` app and space in the platform document, the policy `attachable = false`; the platform's `Anyone` bindings apply to every tenant, anonymous included, as a 7.x global policy did. An attachable policy goes to the platform (default) or, with `--partition by-owner`, to its tenant's document only when it has no DENY statement (a policy with one stays in the platform, because other tenants' principals attached it in 7.x): ALLOW-only by-owner only narrows (C5, recorded).
- **Policy and app conditions.** A policy's condition is a conjunct of each of its statements in 7.x (`Policy.verify`: a failing condition is `IMPLICIT_DENY`, then the DENYs, then the ALLOWs); converted once when both directions agree and otherwise pushed into each statement, each in its own direction; the app condition guards every permission policy the same way.
- **Actions.** Every action of an ALLOW is `http:*`, of a DENY `*` (`MIG-2`, with the C7 and C8 lines); methods are upper-cased as `AbstractActionMatcher` compares them and a method that is not an HTTP token rejects; the pipeline answers 400 to a method with a lower-case letter, so `http:GET` cannot be bypassed by case; arrays and composites merge only when they share their methods; a template in an action, a separator other than `/`, a custom action factory reject. Path patterns go through `HttpPathPattern`, which says it matches what Spring's `PathPattern` matches on its subset (`HttpPathPatternParityTest` compares them; I did not read it) and does not compile what it cannot (`{x:regex}`, an empty pattern, a segment that can be empty): a pattern 8.0 refuses rejects at its statement, a DENY with `decodeAndParseSegments: false` rejects as `DOES_NOT_COMPILE` (DOC-14). The spring-web of 7.x and the one 8.0 compares with may differ in corners I did not look for.
- **Conditions.** `eq`, `in`, `startsWith` evaluate 7.x's predicate on 7.x's reading of an absent part (`""`, and `(0)` for the anonymous principal id) and add `not(exists)` where it holds; `regular` accepts only a literal, a choice of literals and `lit.*` (`LiteralRegex`: I walked `^`, `$`, groups, `|`, escapes, `(?…)` and a nested group, and every other shape reaches a `META` character and returns null); `ignoreCase` is folded beyond ASCII by 7.x, so in a DENY it rejects any value with a letter that folds (the KELVIN SIGN case) and in an ALLOW it records; a part only 7.x filled (`request.attributes.*` but the route id, `resource.*`) is a constant in 8.0 and is rejected in every direction where it would widen or make the DENY vacuous; `contains`, `spel`, `ognl`, custom matchers, `request.remoteIp` strings reject.
- **Time.** `TimeTranslation` passes the configuration through to `Condition.Time` and `TimeChecker` enforces what `TimeConditionMatcher` requires (one of notBefore, notAfter, daysOfWeek or from/to; from and to together; `from != to`; `notBefore < notAfter`); a zone is read as a fixed offset or through `JavaZones`; `from`/`to` with fractions of a second, which 7.x's `LocalTime.parse` accepts, do not parse in 8.0 (rejected, loud). The windows and the day of a window that crosses midnight are 8.0's evaluator's, which I did not read.
- **Rate limits.** Rules are read in the DENY direction (a narrowed rule lets requests escape its limit), go to the platform document, keep 7.x's bucket by key part; `request.remoteIp` as a key becomes `environment.ip` (two spellings of one address share a bucket: limits more, not less).
- **The reader.** `CoSec7xReader` reads CoCache 6's format 1 itself and fails, naming the key, on anything else (a wrong magic, a format, a state, a type); a cached absence or a load lease is a missing value (a lease is a read in progress, not a stored policy, and cannot hold the only copy: Redis is the store of record, and an absent policy is a `GLOBAL_INDEX_WITHOUT_CONTENT` rejection when the index lists it); a Redis Cluster node is refused before a scan; `history:` keys are skipped, and a policy id of that prefix is not a 7.x policy; reserved prefixes, duplicate ids, ids that differ in case (files), `*`, `/`, `:` and unpaired surrogates reject.
- **Tokens.** 7.x tokens keep working in 8.0 with their `roles`, `policies`, `attributes` and `tenantId` (`upgrading.md`, "Tokens and API keys", `MEM-3`), so attached policies, DENYs included, still attach; an attachment of a policy that does not exist is unresolved and permits nothing.
- **Anonymous.** The anonymous principal's tenant is the default one, `(0)`, as in 7.x (`RequestState.anonymous`, `ResolveScope`), its id is absent in 8.0 and `(0)` in 7.x, which `PartTranslation` adds back for the DENY direction.

## What each translator refuses, and how loudly

| Translator | Refuses | Loud? |
|---|---|---|
| `MatcherTranslator` | custom action factories; `#{…}` templates in a path; a separator other than `/`; a method that is not a token; an array or composite whose members have different methods (or mix `all`-with-methods and paths); `*` as a method | rejection with the JSON path; nothing is written |
| `StatementTranslator` | a statement without an action; a condition that can never hold; a DENY left with no action (HEAD alone); a DENY on HEAD without GET; a path condition that reads path variables where it would become the resource | rejection; an ALLOW with no action left is dropped **and recorded** (`PIP-18`) |
| `ConditionTranslator` | `spel`, `ognl`, custom matchers, `contains`, a `path` condition that is not on `request.path`, `inRole` with a malformed value, `inTenant` other than the three | rejection (`EXPRESSION_CONDITION`, `CUSTOM_CONDITION`, `CONDITION_NOT_TRANSLATED`) |
| `PartTranslation` | parts 8.0 has no attribute for; `request.remoteIp` strings; predicates on a part only 7.x filled, in either direction where they would widen or empty a DENY; `endsWith` other than `.domain` with `ignoreCase` on origin or referer host; a template other than the three; case folding beyond ASCII in a DENY; a `regular` that is not a literal shape | rejection with the reason; ALLOW narrowings are recorded (`D1`, `D2`, `D3`, `ASCII-CASE`, `NOT-IN-8.0`, `IP2REGION`) |
| `TimeTranslation` | an unknown field, an unknown day, anything `TimeChecker` or the zone resolver refuses | rejection |
| `RateLimitTranslation` | an undecodable rule, a key part with no attribute | rejection; a translated rule is a `RATE-LIMIT` change |
| `Converter` | reserved or malformed ids, duplicates (also by file name), a schema marker other than 7, an index without content, `GLOBAL` outside the index, a grant of an undefined permission, a document that does not compile as a whole | rejection; **a policy in the index of another type is converted with a warning (R2E-3)**; grants of an app without an app permission are dropped with a warning (their permissions are not defined, so there is nothing to deny) |
| What it converts and a runtime then refuses | `ext.ip2region.country` DENYs: an IPv6 client on a host without an IPv6 database, or without `cosec-ip2region`, is unavailable (ATR-9), so Indeterminate: `503` for every request that DENY is a candidate for | the report (`IP2REGION`, "such a DENY is Indeterminate (503)") and the starter's startup line; not at `convert` time |
| What it converts and a later change then escapes | DENYs and rate limit rules on `http:` or on `resource.id`/`action.verb` (R2E-1) | WARN at install for the first; **none for the second** |

## Notes that are not findings

- C7: a DENY of every action stays `*` and refuses the control plane for the requests it matches; the report records it. A 7.x DENY with no condition on every action already refused every request in 7.x.
- The 7.x blacklist and root are not converted (documented: `BlacklistChecker` becomes a `BlacklistSource`, root becomes break-glass); the application that implemented a `BlacklistChecker` fails to compile against 8.0, so its blocked principals do not vanish unseen.
- `LegacyConversion` and `LegacyReferences` convert the back-references of 8.0.0-beta.4 stores (`MIG-4`), not 7.x data; I read their heads and nothing else.
- `Unreachable.drop` and the `eq` against a template on a part only 7.x filled are the corners where a constant is written as a never-holding condition; each is recorded as `NOT-IN-8.0`.
